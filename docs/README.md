# Tour de Dar Project Documentation

This directory carries the durable context required to continue the project across chats, developers, and phases.

## Reading order

1. [`../AGENTS.md`](../AGENTS.md) — mandatory working laws
2. [`TOUR-DE-DAR-PROJECT-BIBLE.md`](TOUR-DE-DAR-PROJECT-BIBLE.md) — product vision, roadmap, design rules, and phase definitions
3. [`REPOSITORY-CONTEXT.md`](REPOSITORY-CONTEXT.md) — current architecture and implementation state
4. [`DECISIONS.md`](DECISIONS.md) — settled project decisions
5. [`KNOWN-ISSUES.md`](KNOWN-ISSUES.md) — active defects and limitations
6. [`DESIGN-REFERENCES.md`](DESIGN-REFERENCES.md) — approved and superseded visual directions
7. [`ASSET-REGISTER.md`](ASSET-REGISTER.md) — important asset locations and usage
8. Latest numbered file in [`handoffs/`](handoffs/) — current phase status and next task

## Maintenance ownership

| Document | Update when |
| --- | --- |
| Project Bible | Product direction, phases, or permanent rules change |
| Repository Context | Routes, architecture, dependencies, integrations, or shared systems change |
| Decisions | A project-wide product, design, or technical choice is settled or replaced |
| Known Issues | A defect is found, changes status, or is resolved |
| Design References | A visual reference is approved, rejected, or superseded |
| Asset Register | An important asset is added, moved, renamed, or replaced |
| Phase Handoff | A substantial work session ends or a phase is completed |

Never store credentials, environment values, private participant data, or full chat transcripts in these documents.
